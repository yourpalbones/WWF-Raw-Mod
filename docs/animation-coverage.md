## Static Perfect-Plex receiver checks

From `tools/check_perfect_receivers.py` (ROM-free, over `data/perfect-receivers.json`):

- **S1** (pass): Object/tile budget: worst pose uses 17/17 objects and 52/64 tiles including the shadow.
- **S2** (pass): Descriptor chunk order: every pose lists 16x16 objects before 8x8 objects, matching the header count of large objects.
- **S3** (pass): Chunk coverage: with the prototype canvas shift (+9 px x) every pose's chunks span its opaque bounding box, so pieces are not clipped at the canvas edges.
- **S4** (fail): Receiver shadow: the prototype profile draws the body at (32,0) but the Raw shadow part 0x8024 at (0,-1). The shadow stays at the actor origin, visibly detached from the body (gap PP-3). The released v0.16 layout translates every part, shadow included.
- **S5** (info): Constant receiver offset: all 144 poses use one profile offset; the released layout needed a per-frame translate (55-61 px). A single constant cannot reproduce Royal's changing pair spacing unless the attacker/receiver actor spacing is itself held constant by the init hook.
- **S6** (info): Royal receiving art is heavily shared across Royal workers: selector 0: 142/323 private, selector 1: 68/322 private, selector 2: 214/321 private, selector 3: 58/320 private, selector 4: 184/344 private, selector 5: 27/323 private, selector 6: 9/318 private, selector 7: 177/324 private, selector 8: 26/316 private, selector 9: 250/332 private, selector 10: 10/315 private, selector 11: 15/315 private. Raw insertion must give each Raw slot its own private tile IDs; the prototype de-duplicates by decoded tile bytes, which would alias slots if extended across receivers.
- **S7** (info): Facing: Royal component hflip values [True]; receiver parts keep Royal orientation while the attacker capture is mirrored about x=145 (import_perfect_plex.build). Both must be expressed in the same canonical facing, and the pair spacing sign must follow it (gap PP-1).
