Generated by `tools/derive_perfect_pair_coordinates.py`. **PREDICTION from code and recorded actor positions; renderer assumptions unconfirmed by native trace.**

This is a ROM-free model. It combines the transforms in the builders with actor positions recorded in a native replay: attacker x=314, receiver x=354 (spacing **+40**), both y=232. The init hook shifts both actors by the same clamp delta, so it preserves the tie-up spacing; spacing for other receivers, facings and rope positions is not recorded.

## Reading the table

- The model fixes the receiver as facing opposite the attacker, so exactly one actor is mirrored in every case and every case is a rigid copy of Royal (the "Rigid?" column). The open question is only whether the actor spacing matches the spacing that copy requires. If a trace shows both actors with the same runtime flip, no spacing can register them, and this model does not apply.
- The recorded spacing (+40) is within 2 px of the required spacing only when the attacker is **not** flipped while the receiver is on its right, and the profile dx is negated with facing. Either reflection rule (centre or edge) fits. Under these assumptions the scene renders as a **mirror** of Royal. The receiver body is drawn on the attacker's *left*, while the receiver actor origin, and therefore its profile shadow, stays on the right. One cause would then explain both the entry side swap (PP-1) and the detached shadow (PP-3). The two bodies would stay registered to within 1–2 px, so the overlap on lift frames (PP-2) would need another explanation, such as OAM draw order, a different spacing for that receiver, or routing/upload.
- Cross-check for assumption A1: the imported attacker art is a mirror of Royal's right-facing Perfect. Drawn unflipped, it faces left. A trace of the native tie-up OAM flip bits shows whether Raw's unflipped convention also faces left. If it does not, the imported attacker art is reversed relative to Raw's own art.
- The other assumption sets predict errors of 62–82 px. GIF appearance is not used here to choose between assumption sets.

## What a native trace must confirm before any hook edit

1. Facing word and runtime flip for attacker and receiver on the Perfect-Plex frames, in both facings.
2. The renderer's reflection rule from OAM x for one known object. Measured for one facing: native+8 (see perfect-plex-native-trace.md).
3. Whether profile dx is negated with facing.
4. Actor x/y for each receiver, both facings and near both ropes. Only the Luna run is recorded here.
5. OAM draw order between the two actors on lift frames.
